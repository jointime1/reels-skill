# Кластеризация коммитов в арки

Один коммит редко тянет на рилс. Этот файл — про то, как из 30–100 коммитов за месяц собрать 3–5 арок-кандидатов.

## Что такое арка

**Арка** = серия из 5–20 коммитов, объединённая ОДНОЙ из:

1. **Боль пользователя** — все коммиты решают одну проблему.
2. **Фича** — все коммиты строят одну функциональность.
3. **Инцидент** — все коммиты возникли из одного факапа.
4. **Миграция** — все коммиты участвуют в одном переезде (стек, схема, инфра).
5. **Эксперимент** — все коммиты проверяют одну гипотезу.

## Алгоритм кластеризации

### Шаг A — Собрать сырьё

```bash
# Последние 3 недели — основной материал
git log --since="3 weeks ago" --oneline

# Со статистикой (увидеть размер коммитов)
git log --since="3 weeks ago" --shortstat --pretty=format:"=== %h %ad %s" --date=short

# С телом сообщений (для расширенного контекста)
git log --since="3 weeks ago" --pretty=format:"%h %ad %s%n%b%n---" --date=short
```

### Шаг B — Найти ключевые слова

Извлеки часто повторяющиеся существительные из сообщений коммитов:

```bash
git log --since="3 weeks ago" --pretty=format:"%s" \
  | tr '[:upper:]' '[:lower:]' \
  | tr -c '[:alnum:]' '\n' \
  | sort | uniq -c | sort -rn \
  | head -40
```

Игнорируй стоп-слова (`add`, `fix`, `update`, `the`, `wip`, `и`, `на`).

Что осталось — это вероятные **темы недели**. Например: `payments`, `cache`, `auth`, `migration`, `worker`.

### Шаг C — Сгруппировать коммиты по теме

Для каждой темы из шага B:

```bash
git log --since="3 weeks ago" --oneline --grep="payments"
```

Если для темы набирается **≥3 коммита** — это потенциальная арка.

### Шаг D — Проверить связность файлов

Арка должна не только разделять слова в сообщениях, но и **трогать пересекающиеся файлы**.

```bash
git log --since="3 weeks ago" --name-only --pretty=format:"--- %h %s" \
  | head -200
```

Если коммиты на одну тему трогают разные подсистемы — это две арки, не одна.

### Шаг E — Найти отдельные war-stories

Не только тематические серии, но и:

- **Hotfix-арка** — `git log --grep="hotfix\|urgent\|revert"`. Каждый такой коммит = потенциальный одиночный рилс (см. правила single-commit).
- **Revert-цепочки** — `git log --grep="revert"`. Если был revert + повторный фикс — это готовая комическая арка.
- **Длинные ветки** — `git log --merges --first-parent`. Долгая ветка = долгая история.

## Правило одиночного коммита

Single-commit арка **разрешена только** если:

1. **Hotfix** с реальным downtime / data loss / silent break. Должно быть явно видно из сообщения (`hotfix`, `urgent fix`, `critical`) ИЛИ автор подтвердил.
2. **Milestone** — первый пользователь, первый платёж, лонч, N-й коммит, выкатка.
3. **War story в один день** — коммит-сообщение длинное и описывает приключение целиком.

Иначе — агрегируй или предупреди пользователя.

## Анти-арки (НЕ снимать)

Эти кластеры выглядят как арки, но рилс из них получится скучным:

- **Рутинные обновления зависимостей.** `chore: bump X to Y` × 10 — не история.
- **Чистый рефакторинг без боли.** Если ничего не сломалось и юзер не пострадал — нет ставок.
- **Косметика интерфейса.** Кроме случая, если она исправляет конкретную жалобу юзера.
- **Тесты ради тестов.** Без багов, которые они нашли.

Если арка попадает под анти-арку — score ≤4, не предлагай как кандидата.

## Формат предъявления арки

```
### Кандидат A: Перевозили payments-worker с queue v1 на v2 · score 8/12
- Период: 4 — 11 мая 2026
- Коммиты: 7 штук (abc123 — def456)
- Боль: 12% платежей зависали по 6 часов в очереди
- Виральный угол: ставки (деньги) + твист (фикс в одном yaml-файле)
- Лексикон проекта: payments-worker, retry-storm, dead-letter
- Риск: технический жаргон может перегрузить — потребуется аналогия для очереди
```

Этот формат заставляет одновременно ответить на 6 вопросов: **когда, что, для кого больно, чем виральная, какие конкретные слова из проекта попадут в текст, где можно облажаться на камере**.

## Когда отказать пользователю

Если ни одна арка из последних 3 недель не набирает score ≥5:

- Скажи прямо: «Материала на сильный рилс пока нет. За последние 3 недели — рефакторинг без видимых для юзера эффектов. Подожди следующий инцидент или выпуск».
- Не натягивай сову. Слабый рилс в серии хуже, чем пропущенный день.
- Опционально предложи: «Зато можно сделать рилс не про неделю, а про долгий тренд: что я выкинул за месяц». Это другая категория арки (ретроспектива).
